# Publishing Petron Radar

- **Already deployed** as Replit **autoscale**, public, at the generated `*.replit.app` domain. "Publishing" = re-publish latest code. Recommend the `.replit.app` domain for immediate go-live (auto HTTPS, no DNS).
- **Two services go to prod:** `petron-radar` (static, Vite → `dist/public`, SPA rewrite `/* → /index.html`) and `api-server` (esbuild bundle, runs `node dist/index.mjs`, healthz `/api/healthz`). The `mockup-sandbox` (Canvas) artifact has **no `[services.production]`**, so it is excluded from prod by design.
- **Production DB migration is automatic and SAFE here.** Publish introspects the live dev + prod databases, computes a SQL diff, surfaces renames for confirmation, and applies it.
  **Why this matters:** this project forbids `drizzle-kit push` (it drops the raw-SQL tables `opportunity_portfolio`, `opportunity_documents` not perfectly mirrored). The Publish flow does **NOT** use drizzle-kit push — it diffs introspected schemas — so re-publishing adds missing columns/tables to prod **without dropping** the raw-SQL tables. Do not write migration scripts or deploy/startup DDL; just re-publish.
- **Build needs env to run from bash:** Vite config validates both `BASE_PATH` and `PORT` even for `build`. Verify with `BASE_PATH=/ PORT=18277 pnpm --filter @workspace/petron-radar run build`. (Prefer typecheck; only run build to sanity-check deploy.)
- **MP_WEBHOOK_SECRET is optional.** `validateWebhookSignature` returns `true` when the secret is unset (degrades to accepting webhooks unsigned); payment confirmation also works via status-poll, so a missing secret does not block prod. Add it later to harden webhook signature verification.
- **Prod DB is separate and starts EMPTY of DATA; Publish copies SCHEMA only, not rows.** After publish, all tables have schema but zero rows, so login on the live site fails with "Credenciais inválidas" — there is no admin in prod. The agent CANNOT write to prod (executeSql production is read-only). Login gate is only: row exists, `ativo=true`, bcrypt password match, and a JOIN to `company_accounts` (company_id must exist).
- **"Overwrite data" is UNRELIABLE for account rows — do NOT depend on it.** Re-publishing with the Publish-UI "Overwrite data" option brought over content rows (opportunities/bulletins) but left `company_accounts`/`company_users`/`subscriptions` at **zero**, so every login still failed. Root-caused by read-only prod queries (schema matched dev exactly; the rows simply weren't copied).
- **Seed prod via the authorized, self-disabling bootstrap endpoint.** `POST /api/admin/seed-companies` requires `BOOTSTRAP_AUTH_TOKEN` from Replit Secrets, plus a matching Bearer header, and only runs while `company_users` is empty. The guard and all inserts share one transaction; returned temporary passwords require reset on first login. For a truly empty DB, call the endpoint directly with curl because the Empresas page requires an existing admin session; keep the one-time-password response private. **Why:** publishing copies schema, not accounts, and no admin can sign in to initialize a zero-user database. The token is never in source and requests fail closed if it is missing or weak.
  - **Master/ADMIN_PETRON must also pass the set-password step.** The `WelcomeOnboarding` password gate (App.tsx `showOnboarding`) must fire for ANY `mustSetPassword` user, not just client roles — else an admin seeded with a temp password never gets the reset UI and the temp becomes permanent. Keep the client *tour* role-gated; capture `needsPassword`/`showTour` once on mount so the step array doesn't shrink mid-flow (→ blank modal).
- **Confirm a deploy actually rolled out NEW code WITHOUT a destructive probe.** When old and new code expose the same route (so you can't tell them apart by calling it, and calling the old unguarded seed would write wrong data), compare the deployed Vite asset hash — fetch prod `index.html`, then build locally with `BASE_PATH=/ PORT=<port> vite build`. Identical `assets/index-*.js` hash ⟹ new bundle is live; deploys are atomic so the backend matches. Only then call the one-shot seed.
